It does not lack the tactical pattern. The learned forest does not score

with the broader weakness already observed on EC-negative sacrifice cases.

Why the old sacrifice feature says false
The EC-derived test compares capture-search material estimates. Its code
also recognizes checkmate: material(checkmate)=-10000. A queen capture that
permits Bxf7# is therefore not a profitable capture for Black. The probe
returns0 before and0 afterNe5, failing its material-loss test. A diagnostic
Python reproduction agrees; artificially disabling mate recognition changes
the after estimate to+910 for Black. That artificial switch is explanatory
only, not a proposed change: detecting mate is correct.
This exposes the conceptual difference between losing material against good
play and offering material that cannot safely be accepted. Humans can call
the latter a sacrifice; the inherited EC indicator misses it here.

How the forest uses the information
The newer forest has separate legal-offer and mating-acceptance features,
so it can override the old EC conclusion, but these are learned inputs, not
an automatic mate-sacrifice rule. In this position it sees a noncapturing
knight move exposing an unmoved queen (and also a knight offer), and mixed
short-horizon material outcomes. Those inputs lead to leaves below the
conservative award cutoff.
An artificial one-feature sensitivity check at3M decreases the score from
0.6214 to0.5981 when only mating_acceptance is set false. Setting only
EC-sacrifice true raises it to0.7017, still below cutoff. Therefore no single
boolean alone explains the rejection; the existing mate signal has limited
influence in this feature context. These synthetic feature vectors are not
legal alternative positions and do not justify changing a flag or threshold.

The Good fallback is expected: inherited annotation() sees a best move well
separated from second best, an improvement over the preceding own position,
and ec_sacrifice=false. The forest fails to promote it, so Good remains.

Implication
This is a concrete false negative relative to the desired Mute behavior of
recognizing this classic sound queen offer. It is not a verified Chess.com
label; this game was not reviewed there. More search alone did not cure the
local rejection. A focused future experiment should test a narrowly defined
sound, newly created mating offer with matched ordinary examples, or a model
that better distinguishes this subtype, under the existing grouped controls.
Do not globally award every accepted-piece-mate motif: earlier matched cases
showed such motifs on both sides of the Chess.com label boundary. No rule,
threshold, model, or deployed application was changed for this investigation.
